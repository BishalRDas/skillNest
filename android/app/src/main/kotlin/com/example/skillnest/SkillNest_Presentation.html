SkillNest

On-Demand Local Service Finder & Booking Platform

Software Requirements Specification & System Architecture Design

Created: May 2026

Project Overview & Scope

SkillNest Core
  • Purpose: Connects local manual labor providers (plumbers, electricians, painters) with neighborhood clients.
  • Client SDK: Built entirely using the Flutter cross-platform framework for a reactive mobile experience.
  • Backend Infrastructure: Operates on Google Cloud Firestore (NoSQL datastore) and Firebase Authentication.
  • Core Solution: Translates geographic coordinate picks on maps into city-level search categories, combined with a secure physical OTP check to confirm on-site services.

System Features & Role Partition

Capabilities
  • Customer Workflows: Coordinate selection using OpenStreetMap, location picker, worker searches, OTP tracking, and feedback submission.
  • Worker Workflows: Base64 profile photo parsing, rate configuration, online/offline state switches, booking requests list, and job verification checks.
  • Job Lifecycle Security: Locks worker's status to busy (`isWorking=true`) on acceptance. The job remains locked until the customer's verbal code is validated.
  • Feedback updates: Executes atomic database transactions updating averages and total counts.

Use Case Diagram

System Boundaries
  • Customer (User): Controls account profile setup, coordinates map picking, worker directory lookups, slot configurations, OTP displays, and review inputs.
  • Worker: Toggles availability switches, configures pricing rates, accepts booking requests, and enters verify codes.
  • System Admin: Exercises read-only controls to monitor global users lists, worker directories, and transactional job records.

Entity-Relationship Diagram

Database Schema
  • users collection: Base document containing credentials, location names, coordinate offsets, and role flags.
  • workers collection: Extends the base user registry with skill types, charge rates, average rating, and counts.
  • jobs collection: Records dates, slot times, cost, OTP, and status fields.
  • reviews collection: Captures rating metrics and feedback.

Process Breakdown

  • 3.0 & 4.0: Searching approved providers and submitting job slots.
  • 5.0 & 6.0: Checking OTP codes, verifying presence, and executing reviews.

Sequence Diagram

Transaction Flow
  • Details booking handshake exchanges:
  • Booking (1-3): Customer submits request. Database records pending status.
  • Acceptance (4-8): Worker accepts; system auto-rejects other client requests, locks worker, and generates OTP.
  • Verification (9-15): Worker inputs customer's verbal code, unlocking 'In Progress'.
  • Completion (16-25): Customer releases job, completing payment and rating recalculation.

Technology Stack Summary

• Core Framework: Flutter SDK (Dart) for high-performance reactive clients.

• Database Engine: Google Cloud Firestore NoSQL Database.

• Mapping Services: OSM Tile API using flutter_map wrapper and Geocoding APIs.

• Authentication: Firebase Authentication Services.

• Specifications: Complete SRS, diagrams (Use Case, ERD, DFD, Sequence), and Test Cases.
